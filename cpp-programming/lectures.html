C++ Programming · Lecture programme

Ten accounts of the running program

The lessons supply the detailed course. These lectures hold the larger argument together: objects occupy storage, stored values represent program state, operations change that state, and a programmer must be able to account for the result.

Open Lecture 1Return to the 24 lessons

One argument, developed ten times

A variable is not merely a line of syntax. A pointer is not the object to which it points. A class is not appropriate because it makes the source look organised. Each lecture begins with a claim that sounds plausible, then asks what must be true in the running program before we are entitled to accept it.

The sequence is deliberately concerned with memory and memory representation. It moves from the first local object to function boundaries, builds, control flow, addresses, lifetime, layout and polymorphic views. The final lecture returns to the question that begins the first: what must an appropriate programmer understand, preserve and demonstrate?
